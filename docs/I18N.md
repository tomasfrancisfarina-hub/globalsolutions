# Internationalization (i18n)

> Prepared but not active. Enable when ready for English content.

## Current State

- Feature flag: `features.i18n = true` ✅
- Locales: `es`, `en` — both fully active
- Default locale: `en` (international-first, x-default)
- URL structure: `/es/...` and `/en/...`
- Middleware: auto-redirect + Accept-Language detection

## How to Activate

### 1. Enable the feature flag

```typescript
// config/features.ts
i18n: true,
```

### 2. Create English content

Mirror the Spanish structure in `content/locales/en/`:

```
content/locales/en/
├── home.ts
├── navigation.ts
├── divisions/
│   ├── growth-marketing.ts
│   └── ...
├── case-studies/
└── methodology.ts
```

### 3. Update middleware

The middleware in `middleware.ts` will automatically redirect to locale-prefixed paths when the flag is enabled.

### 4. Update content getters

Modify `lib/content/index.ts` to accept a locale parameter:

```typescript
export function getAllDivisions(locale: Locale = "es"): Division[] {
  // Load from content/locales/{locale}/divisions/
}
```

### 5. Add locale switcher

Unhide `components/layout/locale-switcher.tsx` in the header.

## URL Structure

| Locale | Example |
|--------|---------|
| Spanish (default) | `/divisions/growth-marketing` |
| English | `/en/divisions/growth-marketing` |

When i18n is disabled, all routes work without locale prefix.

## SEO Considerations

- Each locale gets its own metadata (title, description in target language)
- `hreflang` tags added automatically
- Separate sitemap entries per locale
- Canonical URLs per locale

## Multi-Country (v3)

Extend `config/site.ts` with regional configs:

```typescript
regions: {
  es: { locale: "es", currency: "EUR", phone: "+34..." },
  en: { locale: "en", currency: "USD", phone: "+1..." },
}
```
